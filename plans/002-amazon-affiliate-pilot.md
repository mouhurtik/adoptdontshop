## Why this matters

The current site already has a small Amazon catalog, so the first revenue test
does not need a wallet, a new commerce backend, or a large product directory.
The user has explicitly chosen Amazon affiliate links without purchase rewards.
The goal is an observable path from relevant content to a useful product and
provider-reported commission, with no promise about earnings.

## Scope

In scope: `views/AboutUs.tsx`, `views/essentials/productsData.ts`,
`views/essentials/ProductsSection.tsx`, `views/essentials/EssentialsHero.tsx` only
if used by the active surface; existing navigation entries in

only when needed; `lib/analytics.ts`; focused tests under
`views/essentials/__tests__/`; this plan/index. A small shared affiliate-link
component under `components/shop/` is allowed if it replaces repeated behavior.

Out of scope: new checkout, inventory, payment processing, coin balances or reward
RPC calls, bulk merchant catalog imports, `/shop` route migration, live prices,
ratings/reviews scraping, coupons not confirmed by the merchant, unrelated
insurance claims, ad SDKs, or Cuelinks automation before an approved account exists.

## Product contract

1. Reuse the six current slots initially; expand to at most 12 verified products
   when there is a clear owner-selected recommendation. Organise around new dog,
   new cat and everyday essentials using existing dog/cat filtering.
2. Verify each short link's destination and publisher ownership in Associates.
   Use real links generated by the account owner. Never invent a tag, percentage,
   coupon, price or merchant endorsement.
3. Match names/descriptions/images to what the link actually represents. Existing
   generic category imagery must be described as category imagery, not falsely
   presented as a photograph of a specific branded item. Use permitted assets.
4. Keep price copy such as 'Check price on Amazon' rather than manually asserting
   a current selling price or discount without a maintained permitted source.
5. Add a clear affiliate disclosure near the store and the required Amazon
   Associate identification. No PawCoins, cashback, gift or donation incentive is
   attached to visiting Amazon or buying through its links.
6. Make the public store usable without signup. Show a real accessible anchor
   with descriptive text and `rel="sponsored noopener"`; preserve safe new-tab
   behavior if `target="_blank"` is used. Tracking must never delay the click.
7. Initially keep placement contextual: Store navigation and one useful public
   adoption/care entry point. No intrusive modal or forced redirect.

## Steps and verification

### 1. Confirm publisher inputs and catalogue

Create a review list of the six destinations, accurate descriptions, asset rights
and account ownership. Follow redirects for inspection, but do not place a test
purchase or repeatedly generate affiliate traffic. If ownership is unavailable,
prepare the UI locally with the existing entries marked pending review; do not
claim commission is tracked or publish invented links.

Verify: all entries have a known intended destination and publisher approval;
the diff contains no made-up tag, price, discount, rating or reward percentage.

### 2. Improve the existing purchase-intent path

Update `ProductsSection` to use the accessible outbound anchor and verified copy.
Add the disclosure above the recommendations in the active Store tab. Preserve
dog/cat filtering, touch targets, responsive cards, existing redirects and About
tabs. Avoid building a whole new storefront before this path earns evidence.

Verify: `pnpm type-check` exits 0. Focused browser review at desktop and mobile
sizes can reach the Store, switch dog/cat tabs, use Back/Forward and activate a
product with keyboard or touch. `/pet-essentials` still reaches the Store tab.

### 3. Measure clicks without calling them sales

Emit one `affiliate_click` per intentional activation through the shared helper.
Allowlisted fields: stable catalog product ID, merchant `amazon`, product category,
placement `store` or the named public content placement, and `web`/`android` platform.
Never send email, the full affiliate URL, order/customer data, free text or coins.
No purchase event is inferred from a click or an assumed return to the website.

Handle unavailable/blocked analytics as a no-op. Ensure a fast click before GA4's
lazy initialization does not block navigation; queue safely under the chosen
measurement/consent policy or explicitly record the measurement limitation.

Verify with focused tests: correct anchor/destination and disclosure, dog/cat
filtering, event fields, no duplicate activation, and click success when analytics
is absent. Browser collection should show one event with the intended placement.

### 4. Release and review actual commission

Run the release checks below, stage only this pilot, and publish the reviewed
release under the current execution authorization. Record the deployed commit.
Check the deployed route and tracking rather than relying on localhost alone.

Review a complete weekly report of store visitors, outbound clicks, ordered or
shipped items and reported commission. Amazon reporting is aggregate unless the
provider explicitly supplies otherwise; do not attribute an order to a member
using timing or IP guesses. Keep reported commission separate from actual payout.
Run the pilot for at least two complete measured weeks before adding complexity.

## STOP conditions and maintenance

Stop the affected publication step if publisher ownership/approval is unknown,
links lead somewhere unexpected, product content is unsupported, or a change
would reintroduce rewards for Amazon/ad engagement. Do not fabricate inputs to
finish a release. Recheck Amazon's requirements when adding mobile-app traffic;
the Capacitor app is not automatically covered by website approval. Record which
channel is approved and test browser/app checkout during the mobile phase.

Maintain the small catalog regularly. Remove stale or unavailable recommendations
and compare clicks with actual provider reports before adding products or APIs.
